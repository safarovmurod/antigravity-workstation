# Backend: читать только для серверной задачи

Сначала прочитай package manifest, точку входа сервера и один соседний endpoint. Сохраняй действующий framework, язык и способ хранения данных. Не внедряй новый стек ради примера.

До изменения проверь контракт: method, URL, params, body, response, коды ошибок, authentication и authorization. Валидация входа выполняется на сервере; клиентская валидация её не заменяет. Не возвращай secrets, stack traces и персональные данные в ошибках. Используй параметры запросов к БД, транзакции для связанных записей и действующие миграции проекта.

Узкое исправление сохраняет контракт и логику пользователя. Если требуется менять схему, публичный API или другое поведение вне запроса, покажи конкретный diff и дождись согласия. Когда пользователь просит варианты кода, покажи исходный простой вариант, Middle и Architect; примени только согласованное решение.

Проверь успешный запрос, некорректный ввод, отсутствие доступа, несуществующую запись и повторный запрос, если возможны дубликаты. Для UI-потока проверь browser → request → handler → storage → response → UI. Укажи, какие звенья реально проверены.
