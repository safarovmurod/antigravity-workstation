## 3. Antigravity Chat — что найдено и что сделано (требование 7)

**Статическое исследование настоящих бандлов** (установленный IDE `D:\User\Antigravity IDE`, main.js sha256 совпадает с аудированным 2.5.5 из каталога):
- Система хуков реальна: UI и валидация `hooks.json` найдены в `out/main.js` и `out/jetskiAgent/main.js`; события `PreToolUse/PostToolUse/PreInvocation/PostInvocation/Stop` подтверждены.
- Но строки `permissionDecision` и `hookSpecificOutput` — **0 вхождений** нигде (Claude-формат не используется); строка `decision` в main.js/jetskiAgent встречается только внутри библиотеки парсера (chevrotain); `injectSteps` (ключ ответа адаптера на PreInvocation) — **0 вхождений**. Исполнитель хуков, читающий stdout, в локальных бандлах не найден (вероятно, sidecar/удалённый рантайм).
- **Следствие:** нет локальных доказательств, что `{decision:'ask'}` адаптера GSD вызывает диалоги подтверждения; менять его на «allow» без live-доказательств запрещено handoff-ом и было бы неподтверждённой догадкой. Адаптер оставлен без изменений (guard-ы deny работают как раньше). Это гипотеза «не источник запросов», подкреплённая статическим отсутствием обработчика, — не доказанный факт.
- В реальном профиле пользователя rules `ask` **отсутствуют** (5 allow из сетапа, 0 ask/deny) — правила не источник постоянных запросов. Источник запросов — дефолт «спросить» для действий без правил + возможно Secure Mode/аккаунт (вне конфигурации).
- **Сделано:** расширены allow-правила в `config/antigravity-settings.json` (`command(git *)`, `write_file(*)`, `read_url(*)`) — ровно под список жалоб (Git, файлы, URL); MCP уже покрыт нативно `mcp(*) Allow`. Сузить/расширить можно в Settings → Permissions.
- **Честный вывод:** максимум конфигурационного уровня = 3 нативных sentinel'а + allow-правила; обещать «никаких подтверждений вообще» нельзя (Secure Mode, политики аккаунта, неподдерживаемые действия). Live-проверка — после твоего пуша и запуска команды установки, в живом чате.
