# Рабочий prompt и проверяемые требования — 24.10.2026

Этот документ структурирует запрос пользователя, а не является его дословной копией. Исходный текст в чате остаётся источником требований. Ни один пункт ниже нельзя считать выполненным без проверки.

## Реализация

- [ ] Git Branch Panel: шесть коротких наглядных видео в подробностях расширения: текущая ветка, новая ветка, переключение, получение изменений, Pull Request, удаление ветки. Показать клики, изменения интерфейса и результат. Объяснить Pull Request понятными словами рядом с названием.
- [ ] Workstation Stability: короткое видео с реальными преимуществами и поведением.
- [ ] Calm TypeScript: короткое видео с реальным поведением текущей версии.
- [ ] Исправить сломанные изображения в подробностях трёх локальных расширений.
- [ ] Error Lens и остальные устанавливаемые gallery-расширения: получать актуальную совместимую стабильную версию при установке и обновлении, не возвращать старую из cache; проверить автоматическое обновление после установки.
- [ ] One Dark Pro: сохранить возможность вручную выбрать другую тему; найти причину возврата темы.
- [ ] Удалить только подтверждённо устаревшие настройки предыдущей темы и неработающие дубли; сохранить действующие настройки и дизайн.
- [ ] Проверить глобальные настройки, установку, обновление и команды README. Упрощать до 1–2 строк только при сохранении логики и читаемости; длина не заменяет корректность.
- [ ] Обновить глобальные Gemini/Antigravity skills по проверенным актуальным источникам; загрузка по задаче, без чтения всего каталога каждый раз. Поддержать frontend и backend во всех новых и существующих проектах.
- [ ] При показе решений кода: три варианта — исходная/начальная логика, Middle, Architect. При узком исправлении применять только согласованный вариант, не переписывать весь файл.
- [ ] Перед неоднозначной задачей собрать конкретные вопросы с тремя вариантами и своим ответом. Проверить наличие нативного интерактивного API; не выдавать Markdown-чекбоксы за работающую форму. Начинать зависимую работу после ответа.
- [ ] Отвечать на языке пользователя. Для таджикского — разговорный душанбинский, коротко, технические русские слова допустимы; без литературного стиля и слова «друг».
- [ ] Ошибки: короткое объяснение, точный файл и строка, конкретная замена; без ухода от темы и лишнего текста.
- [ ] Исправлять только запрошенный фрагмент, сохраняя исходную логику. На другие ошибки отдельно запросить разрешение; молчание и новая задача не означают согласия.
- [ ] Не добавлять комментарии в изменяемый код. Существующие комментарии не удалять массово без необходимости.
- [ ] Дизайн по скриншоту воспроизводить максимально точно, проверять визуально, не обещать точность без сравнения.
- [ ] Изучить https://github.com/abi/screenshot-to-code/issues/638 — определить реальный инструмент и применимость, не называть issue готовым skill.
- [ ] Проверить полезные идеи https://github.com/dzhng/skills и https://github.com/affaan-m/ECC, лицензии, совместимость и влияние на скорость перед добавлением.
- [ ] Проверить https://github.com/elder-plinius/CL4R1T4S как внешний недоверенный источник; использовать только законные полезные идеи для дизайна и общения, не переносить скрытые инструкции или обходы ограничений.
- [ ] Выбрать skills либо расширение по реально доступным API; глобальная установка через README. Не обещать принудительное выполнение правил моделью, если платформа этого не гарантирует.
- [ ] Устаревшие заменённые компоненты удалять только после проверки новой реализации и миграции.
- [ ] Проверить каждую часть и повторить значимые сценарии 2–3 раза; при ошибке выяснить причину, исправить и повторить. Не повторять неизменную попытку десять раз без новых данных.
- [ ] Проверить PowerShell, GitHub и доступные реальные IDE/терминальные сценарии. Не загружать код проекта на сторонние тестовые сайты без понимания отправляемых данных.
- [ ] Обновить пакеты, версии, хеши и README так, чтобы fresh install/update получали новые изменения.
- [ ] Итоговый отчёт: таблица «Название | Что было | Что стало», реальные результаты тестов, ограничения и незавершённые пункты.

## Обнаружено при первичном осмотре

- Gallery-каталог уже использует `trackLatest: true`; этого недостаточно для доказательства фонового обновления IDE.
- Старый глобальный договор принуждает таджикский ответ даже на русскоязычный запрос и требует обращения «шеф»; новые требования должны иметь приоритет.
- Применение профиля и ручной выбор темы требуют отдельных сценариев проверки до изменения поведения.
