# GitHub Panel 1.4.1 — Setup 3.0.19

## Что было и что исправлено

| Было | Стало |
|---|---|
| Текущая ветка исключалась из Pull | Можно получить `origin/main` в `main`; после fetch используется только удалённая ветка |
| «Принять всё из GitHub» заменяло только конфликтные файлы | Во время конфликтного merge заменяется полное дерево отслеживаемых файлов входящего commit, включая удаление дополнительных отслеживаемых файлов |
| Отсутствовала отдельная страховка полной замены | Перед заменой создаётся `workstation-backup/before-incoming-...`, требуется подтверждение; tree SHA проверяется до commit |
| Форматирование могло молча пропустить отсутствие formatter или неудачное сохранение | Нет результата formatter или сохранения — операция останавливается с понятной причиной; пустой массив edits означает уже отформатированный файл |
| Получение editor settings не учитывало язык документа | Используется document scope: formatter получает языковой tabSize/insertSpaces, в профиле три пробела |
| Длинное содержимое панели могло расширяться за видимую область | Высота ограничена viewport, вертикальная прокрутка, ограниченные списки/textarea и перенос длинных строк |

Полная замена доступна при активном конфликтном merge. Обычный Pull сохраняет merge-семантику. Неотслеживаемые и ignored файлы (`.env`, `node_modules`) не считаются частью дерева GitHub; команда не выполняет `git clean`. Backup сохраняет исходный commit, а не произвольные ручные правки после начала merge. Перед Pull рабочая директория должна быть чистой.

Formatter проекта сохраняет приоритет `.prettierrc`/`.editorconfig`: глобальное значение три пробела не перезаписывает правила чужого проекта. Некорректный синтаксис нельзя безопасно «исправить» принудительным форматированием; ошибка остаётся видимой.

Обновление: команды 1/2 README скачивают Setup 3.0.19 с Panel 1.4.1. Команда 3 остаётся только отключением AI-подсказок.

## Проверка

Новые интеграционные тесты используют настоящие локальные Git repositories и bare origin: same-branch Pull после commit другого clone, повторный Pull, dirty refusal, полный incoming tree SHA, удаление local-only tracked файла и проверка восстановления через backup. Formatter проверяется через контракт API редактора, включая tabSize=3, applyEdit, отказ save и отсутствие provider. Эти тесты не равны проверке интерфейса на пользовательском Windows-компьютере.

Результат локального прогона: 362 Node tests — 342 pass, 20 platform skips, 0 failures. PowerShell: 68 bootstrap scenarios и bundled/repeat/conflicting/corrupt/missing font scenarios прошли. Дополнительно установленный Prettier 12.4.0 extension / bundled engine проверен на TypeScript, JavaScript, HTML, JSON: три пробела и повторное форматирование стабильны; неверный TypeScript отклоняется. Полный Windows IDE UI этим прогоном не проверялся.
