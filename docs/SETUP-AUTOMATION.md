# Автоматии насб — Setup 2.2.0

**Download аз Setup 2.1.9:** командаи README bootstrap-ро бо timeout-и 120 сония ва то 3 кӯшиш мегирад. ZIP timeout-и 600 сония ва то 3 кӯшиш дорад; `curl.exe` истифода мешавад, агар дастрас бошад, вагарна `Invoke-WebRequest` бе progress-и сусти PowerShell. Агар ZIP/download/extraction нашуд, source аз `github.com` бо Git гирифта мешавад — ҳамон SHA, на branch-и дигар ё package-и кӯҳна. Git request-ҳои ноком низ то 3 бор такрор мешаванд. Error марҳила, URL ё сабаби Git-ро нишон медиҳад; HTTP/TLS verification хомӯш намешавад. Ин ислоҳ танҳо download-и setup аст; timeout-и gallery/browser-и беруна метавонад алоҳида рух диҳад.

Як командаи пурраи [README](../README.md#quick-start) bootstrap-и PowerShell-ро аз `main` мегирад. Bootstrap Node.js ≥24, npm ≥10 ва Git-ро месанҷад, зарурат бошад бо `winget` насб мекунад. Баъд commit-и ҷории `main`-ро як бор муайян карда, package-ро аз ҳамон commit мегирад. Install ва Doctor як source-ро истифода мебаранд; нусхаи кӯҳнаи npm cache интихоб намешавад.

Launcher-и 2.2.0 `-MinimumVersion '2.2.0'` медиҳад. Bootstrap identity/version-и source-ро пеш аз иҷрои installer месанҷад ва package-и кӯҳнаро рад мекунад. Download/update-и одӣ ҳамон setup-и пурра бо `--auto-approve` аст: AI Tab/next-edit ва ghost text хомӯш, IntelliSense-и import/variable/path нигоҳ дошта мешавад. `-QuietCompletion` танҳо completion-ро хомӯш мекунад ва иҷозатҳои chat-ро аз нав намегузорад.

Пеш аз lock, cancellation-и request-и пешина, backup ва тағйири production profile, full installer санҷиши read-only-и native bundle, USS schema, database ва preference rows мегузаронад. [Compatibility catalog](../config/native-compatibility.json) ҳоло танҳо build-и audited Windows x64 Antigravity 2.5.5-ро қабул мекунад; версияи нав худкор supported ҳисоб намешавад ва audit-и hash/schema/key/enum мехоҳад. Rules-only ва isolated fixtures native profile-и production-ро тағйир намедиҳанд.

Full installer backup месозад, settings/keybindings/argv-ро менависад, GEMINI.md, rules, skills, agents, guides, hooks, GSD runtime ва local VSIX-ҳоро мегузорад. Profile-и пешфарзи `full` 18 gallery + 3 local extension насб мекунад. `--extension-profile lite` ё `-ExtensionProfile lite` дар bootstrap 8 gallery + 3 local-ро интихоб мекунад. Jelly Cursor ихтиёрӣ аст; catalog ва extension-ҳои мавҷуда дар ҳар ду profile нигоҳ дошта мешаванд. Lite танҳо талаботи насбро кам мекунад ва uninstall намекунад. Интихоб дар `install-options.json` сабт, аз Doctor хонда ва бо backup/restore баргардонда мешавад. [Рӯйхати extension-ҳо](EXTENSIONS.md#full-ва-lite). JetBrains Mono ва agent-browser runtime ҳам дар full install ҳастанд. Ҳар stage error-и худро нишон медиҳад; bootstrap пас аз failure success намегӯяд.

**C: ва D:** насби IDE аз нусхаи кушода, PATH (`antigravity-ide.cmd`, `antigravity.cmd`, `agy.cmd` ё EXE), папкаҳои стандартӣ ва registry ёфта мешавад. Git Bash аз Git-и воқеии PATH ёфта мешавад, аз ҷумла layout-и `mingw64/bin`. GitHub Panel ҳамон CLI ва extensions directory-и ёфташударо мегирад. Settings/backup/font аз `APPDATA`/home/`LOCALAPPDATA`, download аз `TEMP`-и Windows истифода мебаранд; диски IDE онҳоро иваз намекунад. Агар IDE тамоман ёфт нашавад, full install пеш аз навиштан меистад. Portable root-и сабтнашударо бо `ANTIGRAVITY_INSTALL_DIR` нишон додан мумкин.

**Барои насби нав:** интернет, Antigravity IDE ва имкони насби Node/Git лозиманд. `winget` ё Windows метавонад тасдиқи худро талаб кунад. Download-и gallery ва browser runtime аз серверҳои беруна вобаста аст. Login-и account, token ва иҷозатҳои шахсии MCP бо командаи public аз нав сохта намешаванд.

**Барои update:** ownership registry hash-и файлҳои аз setup насбшударо нигоҳ медорад. Файли кӯҳнаи тағйирнаёфтаи payload-и setup тоза мешавад; файли дастӣ таҳриршуда нигоҳ дошта мешавад ва conflict нишон дода мешавад. Ин идоракунии payload-и `.gemini` аст; source file-ҳои project-и user target-и install/restore нестанд. Ягон файли repo барои release-и 2.2.0 ҳазф нашуд. Full backup пеш аз навиштан сохта мешавад. **233 managed setting** ва **15 managed binding** нав мешаванд; key-ҳои бегона, shortcut-ҳои бегона, exclusion path-ҳои иловагӣ ва command deny-ҳои явнӣ нигоҳ дошта мешаванд. Font, theme, formatter, Auto Save ва дигар managed setting-ҳо қасдан аз repo overwrite мешаванд; рафтори варианти 4 бо дархости user тағйир дода нашуд. Native automation аз `settings.json` ҷудо аст: [механизм ва rollback](AGENT-AUTOMATION.md). Launcher-ҳои MCP-и идорашаванда нав мешаванд; credential ва ҳолати enable/disable-и шахсӣ нигоҳ дошта мешаванд. Catalog-и `config/migrations/legacy-payload.json` фақат барои шинохтану тоза кардани bytes/hash-и setup-и кӯҳна аст ва ҳамчун rule насб намешавад.

**Барои санҷиш:** `node bin/mansur-setup.js doctor` файлҳо, versions ва settings-ро месанҷад. Runtime-и AI chat, пайвасти MCP, ҷавоби provider ва UI-и ҳар extension санҷиши алоҳида мехоҳанд. Тестҳои автоматӣ дар `npm.cmd test`, `npm.cmd run test:bootstrap` ва `npm.cmd run test:powershell` ҳастанд; натиҷаи иҷрои ҷории онҳо бояд аз CI ё terminal гирифта шавад, на аз ҳисоботи кӯҳна.

**Status ва recovery:** `npm.cmd run status` ё `node bin/mansur-setup.js status --json` waiting/applied/failed/cancelled/interrupted/expired ва drift-ро фарқ мекунад. `queued` маънои applied надорад. `npm.cmd run resume` request-и protocol-2-и қатъшударо бо ID ва scope-и аслӣ давом медиҳад. Helper 1.2.2 ҳамин recovery-ро дар IDE startup низ кӯшиш мекунад. Completion-only иҷозатҳои chat-ро намегирад; cancellation, request-и нав ё worker-и зинда recovery-и кӯҳнаро бозмедоранд. Worker process-и IDE-ро kill намекунад ва Windows startup task намесозад. Runtime баъди cleanup-и checkout-и муваққатӣ боқӣ мемонад; [commands-и мустақил](RELIABILITY-2.2.0.md#status-and-recovery).

**Як rollback:** backup-и нави install/quiet-completion snapshot-и native-и пеш аз тағйирро пайваст мекунад. Он танҳо owned preference rows-ро мегирад, на account ё database-и пурраро. Full auto-approve terminal/artifact/MCP/Tab-ро соҳибӣ мекунад; skip-permissions/completion-only танҳо Tab; bare install MCP+Tab бо `includeAgentPolicies: false`. `node bin/mansur-setup.js restore --dry-run` ва баъд `restore` ҳар ду қисмро месанҷанд, worker-и интизорро бекор мекунанд ва бо IDE-и пурра пӯшида бармегардонанд. Backup-и кӯҳнаи бе snapshot танҳо файлҳоро бо `complete: false` мегардонад; хатои дертар дар file IO метавонад `partial: true` диҳад. Ин cross-file/database transaction-и atomic нест. [Маҳдудиятҳо ва commands](RELIABILITY-2.2.0.md#one-coordinated-restore).

**Татбиқи воқеии editor:** helper 1.2.2 plan-и идорашавандаро дар startup ва баъди install-и такрорӣ мехонад. Бо `ConfigurationTarget.Global` profile-и фаъоли editor-ро танзим мекунад; settings-и пешинаи ҳамин profile дар global state-и helper нигоҳ дошта мешаванд. Барои request-и аллакай татбиқшуда настройкаҳоро дар ҳар startup аз нав намебандад; install-и нав request-и нав месозад. Unknown setting-и версияи дигар ё extension-и ғоиб ҳамчун `unavailable` дар Output сабт мешавад. Хатои API ва workspace override ҳамчун `needs-attention` нишон дода мешаванд.

Забони русӣ дар argv интихоб ва Language Pack насб мешавад. Барои забон ҳамаи window-ҳои IDE-ро пурра пӯшида, аз нав кушо. Runtime helper `vscode.env.language`-ро мехонад ва English-ро ҳамчун `restart-required` нишон медиҳад. Docker/GitHub MCP аз ҳар ду config тоза мешаванд; backups credential-и қаблиро нигоҳ медоранд.

**Cache-и забон:** CLI метавонад Language Pack-ро сабт кунад, вале `languagepacks.json`-ро насозад. Setup manifest, ID/version-и сабтшуда, JSON ва мавҷудияти translation-файлҳоро месанҷад ва entry-и ru-ро месозад; cache-и забонҳои дигар нигоҳ дошта мешавад. Backup файли пешинаро мегирад. MD5 дар ин файл identifier-и стандартии cache-и VS Code аст; checksum ё TLS-и download суст карда намешавад.

Helper profile-еро танзим мекунад, ки дар он насб/фаъол аст. Барои profile-и номдори алоҳида helper бояд дар ҳамон profile фаъол бошад. Settings як бор навишта мешаванд, вале language ва арзишҳои амалкунанда дар startup аз нав санҷида мешаванд.

**Project conflict бе таҳрир:** **Mansur: Inspect Project Setting Conflicts (Read Only)** ҳамаи registered/маълуми language-ҳо, combined selectors ва workspace folders-ро месанҷад. Report key, effective value, language, scope ва роҳи маълуми source-ро дар Output ва indicator-и status bar медиҳад. Read/parse error success ҳисоб намешавад. Inspector `.vscode/settings.json`, `.code-workspace` ва source-и project-ро тағйир намедиҳад.

**Windows smoke:** workflow-и [native-windows-smoke](../.github/workflows/native-windows-smoke.yml) танҳо runner-и ҷудогонаи GitHub-hosted Windows-ро истифода мебарад. Checksum-и official artifact, native codec/preflight/rollback/status, real IDE extension-host settings/completion, shutdown/reopen ва conflict fixture санҷида мешаванд. CI report/artifact натиҷаи воқеиро нигоҳ медорад. Сохтани workflow ё Linux tests худ аз худ Windows success-ро тасдиқ намекунад; authenticated chat ва ҷавоби model ҳам қисми smoke test нестанд. Далели release-и ҷорӣ: [RELIABILITY-VERIFICATION.json](RELIABILITY-VERIFICATION.json).
