# Полная проверка проекта — Setup 3.0.14

Проверено 21 октября 2026 года. Проверка охватывает содержимое конфигурации, пути установки, объединение существующих файлов, повторный запуск, локальные runtime и три команды README. Найдены и исправлены два дефекта native hooks: формат события и неверная папка назначения. **263 управляемых параметра, 16 записей клавиш и 1068 файлов payload** проверены после полной установки в изолированный профиль с пробелами в пути.

## Что исправлено

В `config/hooks.json` событие `PreInvocation` содержало команду напрямую. Antigravity IDE 2.5.5 требует группы `{ "hooks": [...] }` для всех пяти типов событий. Старое событие не проходило проверку, из-за чего IDE могла отвергнуть весь файл hooks.

Кроме того, прежний setup записывал hooks в `.gemini/config/hooks.json`. Настоящий экран Customizations IDE читает другой путь: `.gemini/<product.applicationName>/hooks.json`. В официальной 2.5.5 `applicationName` равен `antigravity-ide`. Теперь установщик, Doctor и backup/restore используют **`.gemini/antigravity-ide/hooks.json`**. Путь определяется по product metadata, отдельно от общей папки `config` для MCP. Тест прослеживает обе цепочки в официальном bundle; Windows smoke проверяет файл по product metadata до открытия IDE.

Теперь `PreInvocation` использует правильную группу. Тест извлекает и выполняет настоящий валидатор из официального Windows `out/main.js`: новая конфигурация принимается, прежняя отвергается. Дополнительно проверяется наличие всех трёх необходимых событий GSD и непустых команд. Неправильный исходный hooks-файл останавливает установку до backup, шрифта и записи профиля.

При миграции плагины из прежнего `.gemini/config/hooks.json` добавляются в native-файл; если одинаковый ID есть в обоих, native-определение имеет приоритет. Старый файл остаётся неизменённым. Backup сохраняет точные оригиналы обоих файлов; rollback восстанавливает их и удаляет только новый native-файл, если до установки его не было. Повтор не создаёт новые копии.

Обновление заменяет управляемые определения событий GSD, сохраняя другие личные плагины и дополнительные поля. Явное `enabled: false` сохраняется; Doctor предупреждает, что GSD hooks выключены. Повреждённый личный плагин не удаляется молча: установка сообщает ошибку до изменения профиля. Изменяемый файл сохраняется в точной резервной копии.

Исправления автоимпорта и диагностики из 3.0.12 сохранены. Пакеты Stability **1.3.8**, Calm TypeScript **3.3.1** и Git Branch Panel **1.3.0** не менялись: их исходники и проверенные пакеты остаются согласованными.

## Три команды README

| Вариант | Что применяется | Что сохраняется |
|---|---|---|
| 1. Установить или обновить | Полная конфигурация, JetBrains Mono, правила, skills, agents, runtime, MCP, расширения, язык и native preferences | Посторонние расширения, личные параметры вне управляемых ключей, MCP credentials, явные запреты команд |
| 2. Полная установка с очисткой расширений | Та же полная конфигурация; исправные управляемые пакеты используются повторно | Посторонние/устаревшие расширения архивируются перед удалением; личные параметры и credentials сохраняются |
| 3. Отключить AI-подсказки | Только native AI Tab/next-edit и editor ghost text, включая активный профиль | Остальная конфигурация, расширения, шрифт и разрешения не переустанавливаются |

Все три launcher требуют **не ниже 3.0.14** и получают актуальный commit `main`. Третий режим оставлен узким по выбору пользователя; для полной настройки нужна первая или вторая команда. Четвёртая команда не добавлена. Шрифт включён в обе полные установки.

Наличие файла не является причиной пропустить его содержимое. Установщик вычисляет ожидаемые значения, сравнивает их с текущими и применяет правила владения из таблицы ниже. Исправный пакет расширения пропускается по проверенной версии/регистрации и содержимому, а не только по имени папки. Проверка Marketplace может обращаться к сети без повторной загрузки самого пакета.

## Что требует проверки на конкретном ноутбуке

Полная установка применяется глобально для текущего пользователя. Проектные `.vscode/settings.json`, `.editorconfig` и `.prettierrc` могут иметь более высокий приоритет; установщик не переписывает чужой проект автоматически. Stability/Doctor показывают соответствующие расхождения.

В реальном тестовом Antigravity зарегистрированы и эффективны **247 из 263** ключей. Остальные 16 условны: 12 переключателей Jelly, 3 voice и 1 MSSQL. Они требуют соответствующего расширения/provider. MSSQL schema проверена по официальному Microsoft manifest 1.46.0; SQL-подключение не проверялось. Полный Linux UI-сценарий с физическим Tab остановился на Loading snippet-widget; отдельные native-команды раскрытия `rfc/rafce` и Emmet прошли. Этот результат не заменён фиктивным успехом.

### Повторная проверка: что может не влиять на конкретный файл

Все 263 текущих ключа и исходных значения повторно сопоставлены с сохранённой проверкой registry настоящего IDE: состав и значения совпали. Старые неподдерживаемые `javascript.suggest.importStatements`, `typescript.suggest.importStatements` и `editor.renderValidationDecorations` отсутствуют. Ошибок записи управляемых параметров в этом профиле нет. **247 — число зарегистрированных ключей при общей проверке; оно не означает одинаковое поведение каждого языка.**

В той же реальной проверке API зафиксированы языковые defaults с более высоким приоритетом, чем общий параметр:

| Параметр | Общая настройка | Фактическое языковое значение |
|---|---|---|
| `editor.suggest.insertMode` | `insert` | `replace` для HTML, CSS, SCSS, JSON, JSONC, snippets, Less и Handlebars |
| `editor.tabSize` | 3 | 2 для YAML, Docker Compose, prompt, instructions и chatagent |
| `editor.insertSpaces` | `true` | `false` для Go и Makefile: языковой режим использует Tab |

Это 15 наблюдений по трём параметрам. Ещё четыре отличия `editor.quickSuggestions` используют эквивалентные записи `true/false` и `on/off`; они не обозначают исчезновение подсказок. Языковые defaults сохраняются; принудительные пробелы в Makefile могли бы нарушить его синтаксис. Для десяти управляемых web-языков отступ 3 пробела задан явно в их блоках.

В самом конфиге также есть четыре буквальных значения `ignore`: два `*.format.semicolons` сохраняют стиль точки с запятой встроенного JS/TS formatter, а `css.lint.unknownAtRules` и `scss.lint.unknownAtRules` скрывают предупреждения о неизвестных at-rules, включая Tailwind directives. Основная проверка JS/TS и CSS остаётся включённой; фактическое форматирование управляемых web-файлов выполняет Prettier.

Повторно выполнены **27/27** тестов: приоритет project/workspace/language settings, все режимы установки, выполнение hooks, миграция и rollback. Конфликты чужого `.vscode/settings.json` можно увидеть через Ctrl+Shift+P → **Workstation: Inspect Project Setting Conflicts (Read Only)**. Личный ноутбук и его проекты этой облачной проверкой не прочитаны.

Native preferences и язык требуют сохранить работу, нормально закрыть **все** окна Antigravity и открыть IDE заново. Пока worker ожидает закрытия, статус `pending` является реальным ожиданием, а не завершённой настройкой. Secure Mode, enterprise/project policies и учётная запись могут ограничивать runtime независимо от сохранённых preferences.

Наличие правил/skills/hooks не доказывает выполнение каждой инструкции моделью. Авторизация GitHub, billing/AI credits, живой ответ модели, вызов hook из авторизованного чата и успешная автоматическая отправка каждой repair-задачи не объявляются проверенными только по JSON. При ошибке setup формирует английскую repair-задачу с выбранным scope; доставка в чат, буфер и файл имеют отдельные fallback-проверки. Незавершённая установка остаётся отмеченной как незавершённая.

SHA-256 проверенного ZIP: `4df0bd963b6c6706fec5408fc8630e77d993838a0c69b46b24b1cb5dff8daf85`. В пакете есть обе правки native hooks, безопасная миграция и три version guard 3.0.14. Видео MP4 остаётся в отдельной media-ветке и не увеличивает установочный ZIP.
