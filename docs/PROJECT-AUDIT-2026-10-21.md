# Полная проверка проекта — Setup 3.0.13

Проверено 21 октября 2026 года. Проверка охватывает содержимое конфигурации, пути установки, объединение существующих файлов, повторный запуск, локальные runtime и три команды README. Найден и исправлен дефект native hooks. **263 управляемых параметра, 16 записей клавиш и 1068 файлов payload** проверены после полной установки в изолированный профиль с пробелами в пути.

## Что исправлено

В `config/hooks.json` событие `PreInvocation` содержало команду напрямую. Antigravity IDE 2.5.5 требует группы `{ "hooks": [...] }` для всех пяти типов событий. Старое событие не проходило проверку, из-за чего IDE могла отвергнуть весь файл hooks.

Теперь `PreInvocation` использует правильную группу. Тест извлекает и выполняет настоящий валидатор из официального Windows `out/main.js`: новая конфигурация принимается, прежняя отвергается. Дополнительно проверяется наличие всех трёх необходимых событий GSD и непустых команд. Неправильный исходный hooks-файл останавливает установку до backup, шрифта и записи профиля.

Обновление заменяет управляемые определения событий GSD, сохраняя другие личные плагины и дополнительные поля. Явное `enabled: false` сохраняется; Doctor предупреждает, что GSD hooks выключены. Повреждённый личный плагин не удаляется молча: установка сообщает ошибку до изменения профиля. Изменяемый файл сохраняется в точной резервной копии.

Исправления автоимпорта и диагностики из 3.0.12 сохранены. Пакеты Stability **1.3.8**, Calm TypeScript **3.3.1** и Git Branch Panel **1.3.0** не менялись: их исходники и проверенные пакеты остаются согласованными.

|---|---|---|

| 3. Отключить AI-подсказки | Только native AI Tab/next-edit и editor ghost text, включая активный профиль | Остальная конфигурация, расширения, шрифт и разрешения не переустанавливаются |

Все три launcher требуют **не ниже 3.0.13** и получают актуальный commit `main`. Третий режим оставлен узким по выбору пользователя; для полной настройки нужна первая или вторая команда. Четвёртая команда не добавлена. Шрифт включён в обе полные установки.

Наличие файла не является причиной пропустить его содержимое. Установщик вычисляет ожидаемые значения, сравнивает их с текущими и применяет правила владения из таблицы ниже. Исправный пакет расширения пропускается по проверенной версии/регистрации и содержимому, а не только по имени папки. Проверка Marketplace может обращаться к сети без повторной загрузки самого пакета.

## Что требует проверки на конкретном ноутбуке

Полная установка применяется глобально для текущего пользователя. Проектные `.vscode/settings.json`, `.editorconfig` и `.prettierrc` могут иметь более высокий приоритет; установщик не переписывает чужой проект автоматически. Stability/Doctor показывают соответствующие расхождения.

В реальном тестовом Antigravity зарегистрированы и эффективны **247 из 263** ключей. Остальные 16 условны: 12 переключателей Jelly, 3 voice и 1 MSSQL. Они требуют соответствующего расширения/provider. MSSQL schema проверена по официальному Microsoft manifest 1.46.0; SQL-подключение не проверялось. Полный Linux UI-сценарий с физическим Tab остановился на Loading snippet-widget; отдельные native-команды раскрытия `rfc/rafce` и Emmet прошли. Этот результат не заменён фиктивным успехом.

Native preferences и язык требуют сохранить работу, нормально закрыть **все** окна Antigravity и открыть IDE заново. Пока worker ожидает закрытия, статус `pending` является реальным ожиданием, а не завершённой настройкой. Secure Mode, enterprise/project policies и учётная запись могут ограничивать runtime независимо от сохранённых preferences.

Наличие правил/skills/hooks не доказывает выполнение каждой инструкции моделью. Авторизация GitHub, billing/AI credits, живой ответ модели, вызов hook из авторизованного чата и успешная автоматическая отправка каждой repair-задачи не объявляются проверенными только по JSON. При ошибке setup формирует английскую repair-задачу с выбранным scope; доставка в чат, буфер и файл имеют отдельные fallback-проверки. Незавершённая установка остаётся отмеченной как незавершённая.

Проверка опубликованного commit и новый Windows CI фиксируются после публикации исправления; результаты прежнего release не считаются результатами нового кода.
