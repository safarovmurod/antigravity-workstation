Замима таърихи талабҳост; вазифаи ҳозира иҷрои ҳамин промти ислоҳӣ аст. Checklist-и тоза аз матни аслӣ ҷудо бошад; summary-ро «1:1» нагӯ. Ин промт барои сар кардани кор худкифоя аст.

3. Ҳашт видеои кӯтоҳи воқеӣ соз

Ҳоло docs/feature-guides ҳашт GIF/MP4 дорад, аммо scripts/build-feature-guides.cjs онҳоро аз се карточкаи матнӣ месозад. Инҳо нишон додани кликҳои воқеӣ нестанд. Барои ҳар мавзуъ сабти воқеии версияи ҳозираи Antigravity ва extension-и насбшуда соз:

1. Текущая ветка — чӣ аст, кадом ветка фаъол аст, commit ба куҷо меравад ва танҳо дидани он файлҳоро иваз намекунад.
2. Новая ветка — интихоб кардани base, ном, create, веткаи фаъол ва натиҷа дар local/origin. Дар коди ҳозира branch баъди create ба origin push мешавад; инро ҳам нишон деҳ.
3. Переключить ветку — аз куҷо интихоб мекунӣ, номи ветка ва файлҳо чӣ хел иваз мешаванд, бо unsaved/uncommitted work чӣ мешавад.
4. Получить изменения — source ва current branch, fetch/merge, кадом файлҳо иваз шуданд, conflict чӣ хел мебарояд ва кай push лозим мешавад.
5. Pull Request — паҳлуи номи англисӣ сода фаҳмон: «Пешниҳоди якҷоя кардани кодҳои ин ветка бо веткаи дигар». Дар видео head/base, diff, саҳифаи GitHub ва фарқи кушодани PR аз merge-и воқеиро нишон деҳ.
6. Удалить ветку — кадом ветка, local ё origin ё ҳар ду, confirmation ва натиҷа; кори ҳифзнашуда/commit-ҳои merge-нашуда чӣ мешавад.
7. Workstation Stability — фоидаи воқеӣ: profile, status, conflict detection, ҷойи файли конфликт ва command-ҳои коркунанда.
8. Calm TypeScript — before/after-и воқеӣ, ошибкаҳои ҳанӯз намоён, autocomplete/auto-import-и коркунанда, Settings ва Reset.

Ҳар ролик кӯтоҳу фаҳмо: аз куҷо сар мекунӣ → кадом кнопкаро пахш мекунӣ → чӣ ва дар куҷо иваз шуд. Cursor, матн ва натиҷа хонда шаванд; caption ё шарҳи кӯтоҳи фаҳмо бошад. Операцияи сустро тез карда нишон додан мумкин, аммо натиҷаи сохта не.

Ҳамаи 8 ролик аз «Подробнее»-и extension-и насбшуда кушода шаванд. README-и source танҳо кофӣ нест: VSIX/install/update, media URL, GIF preview, MP4 playback, reload ва бозкушоиро санҷ. Медиа аз версияи ҳозира бошад. Видеои кӯҳнаи 3.0.11 ва screenshot-и Calm 3.3.0-ро ҳамчун далели версияи нав истифода набар; нав кун ё historical нишон деҳ.

4. Git Panel ва мувофиқати видеоро ба код дуруст кун

Дар extensions/git-branch-panel/extension.js:1031–1038 confirmation фақат номҳои веткаро мегӯяд, аммо 1068–1081 local branch-ро бо git branch -D ва origin-ро ҳам нест мекунад. countUnmergedCommits ҳаст, вале handler истифода намекунад. Дар тест бо як commit-и merge-нашуда ҳар ду ref баъди confirmation-и умумӣ нест шуданд.

Scope-и delete-ро пешакӣ равшан нишон деҳ, commit-ҳои unmerged/unpublished-ро санҷ, delete-и оддиро default кун ва force/delete-и remote-ро бо интихоби равшан иҷро кун. Protected branch ва нигоҳдории кори корбар боқӣ монанд. Ин тағйир аз видеои нав ва regression test гузашта бошад.

Барои PR санҷ, ки head/base дар remote ҳастанд; branch-и local-only ё head-и push-нашударо ҳамчун compare-и тайёр нишон надеҳ. Агар push лозим бошад, сабаб ва scope-ро нишон деҳ. Барои санҷиш repo/branch-и disposable истифода бар; ягон PR/merge/delete-и бегона накун.

Получить изменения ва дигар кори дурусти мавҷударо бе зарурат аз нав насоз. Видео ва текст бояд айнан ба рафтори ҳақиқии кнопка мувофиқ бошанд.

5. Error Lens ва дигар extension-ҳо ҳамеша актуалӣ бошанд

trackLatest:true ва интихоби latest stable compatible аллакай ҳаст; онро нигоҳ дор. Барои Error Lens ва ҳамаи gallery extension-ҳо ҳам install ва ҳам update версияи навтарини stable-и мувофиқ ба IDE/OS/architecture-ро интихоб кунанд. Агар absolute latest incompatible бошад, аниқ навис: latest compatible кадом аст ва чаро.

Талаби ман фақат як бор версия нав кардан нест: баъд ман дар репо дигар commit накунам ҳам, гирифтани update бояд кор кунад.

Ҳозир lib/extensions.js:363–420 gallery-ро аз файли VSIX насб мекунад. Дар VS Code чунин насб default метавонад auto-update-и ҳамон extension-ро хомӯш кунад. Дар худи Antigravity per-extension auto-update/pinned state ва gallery-и воқеиро санҷ; танҳо extensions.autoUpdate=true-ро далел нагир. Install-и версияи кӯҳна → пайдо шудани версияи нав → update → restart-ро нишон деҳ. Роҳи иҷрошуда бояд ба IDE-и ҳозира мувофиқ бошад.

Барои extension-ҳои маҳаллии Workstation низ механизми update ва манбаи версия равшан бошад. Онҳоро бо auto-update-и Marketplace як чиз ҳисоб накун. Агар update аз release/README меояд, онро бо роҳи воқеии навшавӣ ва санҷиш пайваст кун; version pin-и кӯҳна ё cache набояд silently баргардад.

Суръатро ҳам ислоҳ кун: ҳоло аввал VSIX-и пурра download мешавад, баъд версия муқоиса мешавад. Аввал metadata/compatibility ва installation-и дурустро муқоиса кун; файлро фақат барои missing/corrupt/new version download кун. Тести repeat бояд бо trackLatest:true-и production бошад; trackLatest:false тести дигар аст. Network error-ро ҳамчун «latest насб шуд» нишон надеҳ.

Агар ҳамон кор бо 1–2 строкаи сода ва хондашаванда иҷро шавад, кӯтоҳ кун. Аммо error handling, request flow, checks, backup ва rollback-ро барои кам кардани строка напарто. Кӯтоҳии зоҳирӣ бе нигоҳдории логика мақсад нест.

8. Қоидаҳои рафтори Gemini-ро якхела кун

Як қоидаи асосӣ бошад ва тамоми skill/reference-ҳо ба он мувофиқ шаванд. Дар baseline ихтилоф ҳаст: core comment-ро манъ мекунад, design-and-code/project-coding-rules comment талаб мекунанд; core ҳам «сразу делай» ва ҳам «аввал савол» дорад; backend се вариантро фақат бо request мегӯяд. Инҳоро пурра мувофиқ кун.

Қоидаҳои ман:

- Забони ҷавоб аз забони паёми ман бошад: русӣ → русӣ, тоҷикӣ → тоҷикӣ, дигар забон → ҳамон забон.
- Барои тоҷикӣ: лаҳни оддии Душанбегӣ, кӯчагӣ, фаҳмо; калимаҳои адабии маҷбурӣ истифода набар. Терминҳои русии оддӣ мумкин. Муроҷиати сохта ва гапҳои лишний даркор нест.
- Update-и кор 1–2 калима ё хеле кӯтоҳ бошад. Ошибкаро аввал бо 2–3 калимаи фаҳмо бигӯ, баъд файл/строка ва ивази аниқро нишон деҳ. Маълумоти зарурро барои кӯтоҳӣ гум накун.
- Аз тема набаро; натиҷаро равшан гӯй ва кори супоридаро иҷро кун.
- Дурӯғ нагӯ: файл навиштан ≠ feature-и санҷидашуда, mock ≠ live Gemini, checkbox-и матнӣ ≠ формаи коркунанда. Кореро, ки накардаӣ, «кардам» нагӯ.
- Ҳар вақте код медиҳӣ, се варианти алоҳида нишон деҳ: 1) Сода/исходный — ҳамон логика ва услуби коди ман; агар новичок бошад, дар сатҳи новичок ислоҳ кун. 2) Middle — ҳамон масъаларо бо тарҳи миёнаи фаҳмо ҳал кун. 3) Architect — ҳамон талабро бо варианти асосноки архитектурӣ нишон деҳ.
- Се пешниҳод маънои се implementation дар project-ро надорад. Фақат варианти интихобшуда/аллакай иҷозатдода татбиқ шавад; варианти пешрафтаро худсарона ҷойи логикаи ман нагузор.
- Агар ман «ҳамичара ислоҳ кун» гуфта порчаи код фиристам: фақат ҳамон порчаро ислоҳ кун; файлро пурра rewrite, rename/refactor ё logic replacement накун, агар барои ҳамон ислоҳ шарт набошад ва иҷозат надошта бошӣ.
- Дигар ошибка ёфтӣ: файл, строка, проблемаи кӯтоҳ ва заменаашро ҷудо нишон деҳ ва пурс «Ҳами строкаҳоям проблема доран, иваз кнм?». Фақат баъди ҷавоби равшан мисли «хо», «бале», «yes» ё ҳаммаъно иҷро кун. Молчание, дигар код ё иваз шудани тема иҷозат нест.
- Қоидаи comment танҳо дар core намонад. Ба коди нав comment нагузор. Талаби «дар проект comment набошад»-ро барои cleanup-и иҷозатдодашуда санҷ: comment-ҳои оддии нолозими коди худи проектро бе вайрон кардани кор тоза кун. Directive-и compiler/tooling, license notice ё comment-и ба runtime таъсирдорро кӯр-кӯрона напарто; ин истиснои маҷбуриро бо сабаб дар отчёт нишон деҳ.
- Дизайни аз screenshot дархостшударо 1:1 иҷро кун: layout, spacing, size, typography, color, assets ва ҳолатҳои намоён. «Ба ҳамин монанд» ҷойи натиҷаи санҷидашуда намегирад.

11. Проверкаи воқеӣ ва retries

Корро ба қисмҳо анҷом деҳ; ҳар қисми тайёрро санҷ, баъд ба дигараш гузар. Дар охир ҳамаи ID-ҳоро боз муқоиса кун.

Се даври маънодор гузарон:

A) clean/fresh install дар profile-и disposable.
B) update аз profile-и пешина бо настройкаҳои шахсӣ, theme-и дигар ва extension-ҳои мавҷуда.
C) repeat update + restart + кушодани проекти наву куҳна + rollback-и санҷишӣ.

PowerShell/Windows, Git/GitHub, install/update-и README, package/source/installed versions, theme preservation, ҳар 8 видео дар Details, deletion/PR/merge ва рафтори rules/skills-ро бо санҷиши мувофиқ фаро гир. Ҳар сценарияи муҳим 2–3 бор дар ҳамин даврҳо натиҷаи устувор диҳад.

npm test, тестҳои PowerShell, native Windows ва дигар suite-ҳои дахлдорро иҷро кун. Тест барои bug-и воқеӣ ва роҳи user бошад; snapshot-и матн ё assert-и «калима дар файл ҳаст» далели рафтори чат нест.

Барои Gemini тести воқеӣ дар project-и нав ва existing гузарон: Tajik/Russian, frontend/backend, се вариант, minimal fix, дигар ошибка бе consent, consent-и равшан, ignoring/new task, comments, screenshot ва questionnaire Submit/Cancel. Transcript ва diff-и натиҷаҳоро сабт кун. Қоида дар файл танҳо instruction аст; рафтори моделро алоҳида санҷ.

Сайтҳои мувофиқи code/terminal testing-ро ҳам, ки дархост кардаам, ҳангоми дастрас будан истифода кун. Фақат коди публичӣ/fixture-и бехатар равон шавад, бе token ё конфиги шахсӣ. GitHub Actions-ро ҳамчун «ба дигар тестерҳо даромадам» ҳисоб накун. Агар ягон сайт/платформа дастрас набошад, URL, санҷиш ва сабабро аниқ навис.

Баъди 1–2 кӯшиши ноком вазифаро напарто. То 10 кӯшиш ё роҳи алтернативии асоснок санҷ, агар роҳи иҷозатдодашуда ва маънодор вуҷуд дошта бошад: сабаб → тағйир/роҳи дигар → натиҷа. Як кори бетағйири нокомро 10 бор такрор накун. Вкладка/инструменти лозимро кушо; permission ё approval rejection-ро давр назан. Blocker-и ҳақиқиро бо далел гузор ва тамоми қисми дигарро анҷом деҳ.

PASS/FAIL/SKIP/BLOCKED/NOT TESTED-ро омехта накун. Тести release-и пешина далели commit-и нав нест. Агар ошибка омад, сабабро ислоҳ кун ва тести ҳамон ошибка ва regression-и дахлдорро такрор кун.

12. README, package ва update якдигарро мувофиқ кунанд

README ва user docs ҳамаи тағйиротро бо командаҳои воқеан коркунанда нишон диҳанд. Ҳозир README ба docs/GITHUB-PANEL-1.4.3.md линк дорад, аммо файл нест — ислоҳ кун ва link-check гузарон.

Baseline аллакай current main-ро мегирад ва MinimumVersion 3.0.24 дорад. Ин freshness guard-ро нигоҳ дор. Барои версияи нави воқеӣ package/version, VSIX, checksum/manifest, bootstrap minimum ва docs-ро мувофиқ нав кун. Source-и GitHub, package-и гирифташуда ва версияи насбшуда ба ҳам рост оянд.

Ҳар rule/skill/video/extension-и нав аз роҳи install/update-и худи README ба ҷойи дуруст расад. Дар source мондану насб нашудан иҷрои вазифа нест. Cache/downgrade, download-и нопурра, update-и такрорӣ ва ҷои path бо пробелро санҷ.

Компоненти кӯҳнаро фақат баъди санҷидани replacement ва migration тоза кун. Account, permissions-и бегона, branch protection ё файли project-и корбарро барои сабз кардани тест дигар накун.
