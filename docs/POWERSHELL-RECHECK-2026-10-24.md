# Повторная проверка PowerShell — 24 октября 2026

Проверяемая версия установки: Setup 3.0.20, Panel 1.4.2. Среда — PowerShell 7 на изолированном Linux-сервере; Windows PowerShell 5.1 и Windows GUI в этой сессии недоступны.

## Что дополнено

HTTP regression раньше запускался только на Windows, проверял успешный ответ и не мог выполняться в текущем облаке. Теперь он запускается и с PowerShell 7 на Linux. На Windows по-прежнему проверяются оба shell: powershell.exe и pwsh. Workflow запускает HTTP regression на всех runner OS.

Используется настоящий HTTP server с настоящими curl и Invoke-WebRequest. На Linux реальный curl доступен под именем curl.exe только в одноразовой тестовой папке; production bootstrap не изменяется. Второй режим явно отключает curl для проверки Invoke-WebRequest.

Три назначения: обычный путь, путь длиной 360 символов, Unicode/пробелы/квадратные скобки. Четыре ответа сервера: корректный файл, временный 503 с успешным retry, пустой ответ и оборванный Content-Length. Для ошибочных ответов проверяются ровно две попытки и отсутствие оставшегося частичного файла. Всего 24 комбинации назначения/ответа/транспорта на PowerShell 7; на Windows два shell дают 48 комбинаций.

Исправлена переносимость защитной проверки cleanup в тесте: учитываются оба разделителя каталогов. Имя Unicode строится из кодовых точек, чтобы чтение script без BOM в Windows PowerShell 5.1 не искажало название папки.

Новых подтверждённых ошибок production bootstrap этим прогоном не найдено; изменения касаются покрытия тестами и их запуска. Скрипты установки и пользовательские настройки не переписывались.
