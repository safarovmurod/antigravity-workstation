# Проверка Windows и защита исходных файлов — 3.0.17

## English task prompt

1. Preserve the user's editor style, chosen settings, agents, rules and extension profiles.
2. Test the existing Windows installer on available x64 and ARM64 Windows runners. Do not add a Linux installer.
3. Test fresh installation, update, unchanged repeat, cleanup and AI completion disable mode.
4. Test missing, empty and corrupted source files, network failures and recovery diagnostics.
5. Check real IDE behavior separately from file presence and simulated platform checks.
6. Fix confirmed bugs, rerun relevant tests and publish evidence. Do not claim untested operating systems work.

## План

Проверить исходные файлы и установщик; воспроизвести ошибки в изолированных профилях; исправить подтверждённые дефекты; проверить PowerShell и README; запустить Windows CI и настоящий IDE; записать результаты и ограничения.

## Подтверждённый дефект и исправление

Повреждённый исходный `agents/gsd-planner.md` размером 0 байт заменял рабочий файл размером 46 963 байта. Установщик сообщал об успехе. Отсутствующая часть исходного дерева также могла попасть в список устаревших установленных файлов.

Теперь полная установка проверяет источник до создания резервной копии и записи профиля:

- все собранные файлы содержат данные, обязательные области присутствуют;
- обе пользовательские группы правил, оба руководства и глобальная инструкция присутствуют;
- каждый навык из каталога имеет `SKILL.md`;
- файлы GSD совпадают с SHA-256 из поставляемого манифеста.

При повреждении установка останавливается с именем файла. Рабочий профиль и резервные копии сохраняются. Это обнаружение повреждения относительно каталога поставки, а не криптографическая проверка издателя всего архива. Осознанные изменения собственных правил разрешены; их стиль и содержимое не заменены этим исправлением.

Шесть регрессионных сценариев проверяют реальное обновление существующего изолированного профиля и побайтовую сохранность всего профиля после отказа.

## Команды README

Все три команды требуют минимум 3.0.17 и получают текущую ветку `main`.

| Команда | Где запускать | Действие |
| --- | --- | --- |
| 1 | PowerShell внутри Antigravity или отдельный Windows PowerShell | Полная установка/обновление; посторонние расширения сохраняются |
| 2 | Отдельный Windows PowerShell, все окна Antigravity закрыты | Полная установка с очисткой лишних расширений; необходимые проверенные пакеты используются повторно |
| 3 | PowerShell внутри Antigravity или отдельный Windows PowerShell | Только отключение AI-подсказок |

При запуске команды 2 внутри IDE нужно сохранить работу, нормально закрыть IDE и запустить команду в отдельном PowerShell. Принудительное завершение IDE не используется. Нельзя копировать строки ограждения Markdown или приглашение `PS>` вместе с кодом.

## Матрица проверки

Setup checks: Windows Server 2022 x64, Windows Server 2025 x64, Windows 11 ARM64; каждая система с Node.js 24 и 26. Существующая Ubuntu-проверка остаётся проверкой переносимых частей, а не полной установкой Linux.

Native Windows smoke: официальный закреплённый Antigravity, отдельные профили на Windows Server 2022/2025 x64 и Windows 11 ARM64. Проверяются установка расширений, повторный запуск, настройки и команды настоящего IDE.

Настройка поддерживает Windows 10 x64 начиная с build 19041 и Windows 11 x64/ARM64 в пределах требований IDE и Node.js. GitHub-hosted Windows Server не доказывает фактический запуск на Windows 10. Windows 7/8, x86 и ARM32 не заявляются совместимыми. Linux не добавляется как платформа полной установки.

Результаты нового запуска CI должны оцениваться по точному коммиту; добавление матрицы само по себе не означает прохождение. Настоящий вход GitHub, ответ модели в чате и доступ к платным сервисам требуют отдельной авторизации и не доказываются проверкой конфигурационных файлов.
