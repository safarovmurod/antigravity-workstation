# GitHub Panel 1.4.0

Панель автоматически работает с Git repository открытой папки. Подключение папки к GitHub выполняется обычными Git-командами в терминале; после `git init` и добавления `origin` панель обнаруживает repository без отдельного запуска. Существующие локальные и `origin`-ветки сохраняются и показываются в списках.

## Commit и push

В блоке текущей ветки показан точный маршрут: выбранные файлы → целевая ветка → `origin/ветка`. Пользователь выбирает файлы флажками. Секретные имена файлов блокируются. Перед изменением Git панель показывает модальное подтверждение.

Флажок «Создать новую ветку для этих изменений» переносит рабочие изменения в новую ветку. Исходную ветку можно выбрать: `main`, текущую или любую существующую. Выбранные файлы попадают в commit; остальные рабочие изменения сохраняются. Если перенос между основами конфликтует, исходные данные дополнительно остаются в `git stash`.

Флажок форматирования вызывает formatter, выбранный самим проектом и редактором. Он не меняет пользовательский `tabSize`: в текущем профиле JavaScript/TypeScript и Prettier продолжают использовать три пробела.

## Получение изменений

Пользователь выбирает исходную ветку, а панель показывает текущую целевую ветку. Затем выполняются `fetch origin --prune` и безопасный merge выбранной ветки в текущую. Новый файл, например `App2.tsx`, переносится полностью.

Если обе ветки изменили один файл, панель показывает каждый конфликт. Можно выбрать текущую или входящую версию отдельно либо применить «Принять всё из GitHub»/«Оставить всё текущее». Отмена выполняет `git merge --abort`. После merge результат остаётся локальным для проверки; отдельный Push публикует его.

## Pull Request и язык

Pull Request не смешивается с Git Pull. Панель открывает официальную страницу сравнения текущей и целевой ветки на `github.com`; окончательное создание подтверждает сам пользователь в GitHub.

Интерфейс использует язык Antigravity: русский locale даёт русский текст, английский — английский, остальные locale получают английский fallback. Техническая ошибка остаётся в output-канале, а панель показывает понятное локализованное объяснение.

`main`, `master` и default branch остаются защищёнными. Активный merge/rebase блокирует несовместимые операции. После push локальный и удалённый SHA сверяются.
