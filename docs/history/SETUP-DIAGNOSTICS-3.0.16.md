# Копирование команд и диагностика установки — 3.0.16

На двух присланных фотографиях показаны разные ситуации.

## 1. PowerShell пытается выполнить обратные кавычки

Во второй фотографии видны обратные кавычки после приглашения `PS ...>` и `CommandNotFoundException`. Это оформление Markdown попало в терминал как команда. Оно не является частью PowerShell-кода установки.

Нажать **Ctrl+C**, затем кнопкой **Copy** справа в блоке README скопировать только выбранную команду: от `& {` до закрывающей `}`. Строки с обратными кавычками, отдельное слово `powershell`, приглашение `PS ...>` и скопированные из лога `>>` вставлять не нужно. Автоматические `>>` во время ввода многострочной команды нормальны. Установщик не может перехватить ошибочный текст, выполненный до его запуска; для этого исправлена инструкция копирования.

## 2. В конце видна только общая ошибка установки

На первой фотографии видна общая строка `Installation failed; read the error above`, путь repair-файла и сообщение о буфере. Исходная стадия и причина обрезаны. Сам по себе этот снимок не доказывает ошибку расширения, шрифта, сети или clean-режима. Пользователь сообщил, что исходный текст передать не может; причина этого отдельного сбоя остаётся **не подтверждённой**.

В 3.0.16 исправлено сохранение причины до последнего сообщения:

- Bootstrap повторяет `[SETUP FAILED]` или `[SETUP INCOMPLETE]`, название стадии, исходную причину и пути **после** вывода fallback/буфера, чтобы они оставались в конце терминала.
- Все три README-команды получают небольшой временный UTF-8 JSON-результат через `-ResultFile`. Он содержит код завершения, состояние, этап и уже очищенную от credentials причину.
- На Windows PowerShell 5.1 вывод native stderr обрабатывается до получения настоящего кода завершения; сам по себе stderr не обрывает launcher до чтения диагностики. После запуска строгая обработка ошибок возвращается.
- При реальной неудаче последняя ошибка README содержит `Setup stopped (exit N). Stage: ... Reason: ...`, а не только общее предложение прочитать строки выше.
- Если JSON отсутствует, повреждён или относится к другому коду завершения, ошибка остаётся ошибкой и сообщает, что сводку получить не удалось. Исходный ненулевой код не превращается в успех.
- JSON ограничен по размеру причины и использует существующее удаление credentials. Файл создаётся с `CreateNew`, не перезаписывает существующий файл/ссылку и удаляется launcher-ом вместе с временным bootstrap. Постоянные setup-логи и repair-файл сохраняются по прежним правилам.

Эти изменения улучшают воспроизведение и диагностику реальных сбоев. Они не являются доказательством исправления неизвестной исходной причины с первой фотографии.

## Где выполнять команды

| Режим | PowerShell в Antigravity | Windows PowerShell из Пуска |
| --- | --- | --- |
| **1. Полная установка/обновление с сохранением остальных расширений** | Да | Да |
| **2. Полная установка с очисткой расширений** | Запускать снаружи IDE | Да; все окна Antigravity должны быть нормально закрыты |
| **3. Только отключение AI-подсказок** | Да | Да |

Эти указания стоят в самих заголовках README и непосредственно перед каждым блоком. В IDE выбрать именно PowerShell; настроенный Git Bash не нужно менять глобально. Отдельное расширение PowerShell для выполнения команд не требуется.

Установка применяется к Antigravity-профилю текущего Windows-пользователя. Папка проекта в приглашении терминала не меняет место установки. Команды 1/3 допускают открытую IDE; native-часть может ожидать нормального закрытия всех окон. Для активации дождаться `applied` и открыть IDE заново.

## Сохранённое поведение

Все три команды требуют **3.0.16**. Команда 1 сохраняет другие расширения, команда 2 сохраняет ранний и повторный clean-guard и паузу exit 3, команда 3 остаётся completion-only. Exit 2 означает ожидающее проверки восстановление. Полная установка по-прежнему требует Doctor. Настройки редактора, шрифта, отступов, прозрачности, keybindings, agents, skills, rules и локальные helper-пакеты не изменены.
