# Повторная установка без лишних копий — 3.0.8

В присланном выводе 3.0.6 второй запуск завершился: **85 Passed, 2 Warnings, 0 Failures**. Все 1068 payload-файлов уже совпадали (`changed: 0`); шрифты и Chrome использовались существующие, расширения сообщали `skipping install`. Повторно скачивался полный source ZIP, создавался новый pre-install backup и выполнялись сетевые проверки Marketplace. Причины отдельного первого неудачного запуска этот успешный вывод не устанавливает.

Все три команды из [README](../README.md#quick-start) теперь используют общий cache проверенного commit:

| Команда | Повторное выполнение |
|---|---|
| 1. Установить/обновить | Сохраняет посторонние расширения; проверяет и переиспользует совместимые установленные пакеты. Неизменившиеся настройки и payload-файлы не переписывает. |
| 2. Очистить лишние и установить полный набор | Сохраняет исправные обязательные пакеты и зависимости; архивирует лишнее, устанавливает недостающее/повреждённое. Для уже чистого набора новый архив не нужен. |
| 3. Отключить AI-подсказки | Использует тот же source cache, меняет только настройки completion и native AI Tab/next edit. Повторный эквивалентный worker не создаётся. |

Полный source архив скачивается один раз на commit. Перед повторным использованием проверяются package identity, полный список файлов и SHA-256 каждого файла. Повреждённая/изменённая копия сохраняется отдельно, новый cache подменяется атомарно. Git fallback, TLS и проверки целостности сохраняются. Небольшой bootstrap и remote `main` по-прежнему проверяются, чтобы получать обновления.

Cache хранит текущий и предыдущий распознанные проверенные commit, по три диагностических запуска на каждый. Проверенный статус native-запросов также ограничен тремя файлами. Общий lock защищает три bootstrap-команды от одновременного изменения одного cache. Длинные пути и кириллица проверены с принудительной OEM437; для рекурсивной уборки используется Node вместо проблемного WinPS provider.

Backup перед реальными изменениями остаётся. Одинаковая повторная установка не копирует заново дерево skills/rules. Маленький request активного профиля обновляется на месте, чтобы helper мог повторно применить настройки именованного профиля. В clean-режиме после успешной установки удаляется только вторая побайтово идентичная копия `removed-tree`; одна проверенная полная recovery-копия остаётся. Если любая из копий изменилась, она сохраняется.

Старые папки предыдущего bootstrap, вручную изменённые/неопознанные данные, незавершённые staging-папки после принудительного убийства процесса и настоящие recovery-backup не удаляются автоматически. Ограничение относится к распознанному исправному cache и статусам, а не ко всем файлам пользователя на диске.

Проверено локально: **322 основных теста, 44 portable PowerShell-сценария, 18 native-schema/automation тестов и 14 smoke guards** без ошибок/пропусков. В их числе — offline reuse всех трёх режимов, повреждённый cache, настоящий cross-process lock, сохранность rollback, неизменные mtime настроек/payload при повторе, dependency closure, один clean-backup вместо двух и стабильное количество архивов при повторном clean.

Рабочий код опубликован в [`d114526`](https://github.com/safarovmurod/antigravity-workstation/commit/d114526d5b5df568d9e942bcc1b4103434f41fee), затем исправлены только тесты в `54f0683` и [`b9f84fb`](https://github.com/safarovmurod/antigravity-workstation/commit/b9f84fb665e9f5d9fbde0e560aef65b6c11c4728). Реальная загрузка последнего commit прошла; сеть source принудительно запрещалась при повторном использовании в normal/clean/quiet, все три режима выбрали ту же проверенную папку. Проверены 1068 payload-хешей, повторное применение конфигурации, quiet-command и согласованный rollback. Внешние Gallery/font/browser downloads этот изолированный live-check не выполняет.

[Native Windows IDE smoke](https://github.com/safarovmurod/antigravity-workstation/actions/runs/39381504312) для рабочего кода `d114526` прошёл на Windows x64 и ARM64 (12 мин 17 с). В full-catalog проверено, что clean-план сохраняет все 25 обязательных пакетов, реально установленных production installer. После этого рабочий код не менялся.

Первый [Setup checks](https://github.com/safarovmurod/antigravity-workstation/actions/runs/39381504245) обнаружил ошибку самого Windows-теста: PowerShell 5.1 терял двойные кавычки JavaScript в `node -e`. Сбой воспроизведён на настоящем коде проверок; передача через stdin исправила обе проверки. Добавлен portable regression в режиме Legacy, уточнена нормализация Windows-путей и вывод исходной ошибки. Production bootstrap уже использовал stdin и для этого исправления не менялся. Повторный [Setup checks](https://github.com/safarovmurod/antigravity-workstation/actions/runs/39382658731) обнаружил ещё одну ошибку теста: один JSON-вызов разворачивался в scalar `PSCustomObject`, для которого WinPS 5.1 не предоставляет `.Count`. Весь результат чтения теперь обёрнут в `@()`. Portable regression исполняет настоящее присваивание и проверяет тип массива для 0/1/2 записей. Последний [Setup checks](https://github.com/safarovmurod/antigravity-workstation/actions/runs/39383270425) для `b9f84fb` прошёл на Linux, Windows x64 и ARM64 (4 мин 13 с). Чтение диагностик теста дополнительно переведено на канонические extended literal paths: их длина в fixture составляет 268–271 символ. Это согласует проверки длинных путей; отдельный сбой runner на этих чтениях не заявляется. После этого все 44 portable-сценария также прошли.

Предыдущий native run `8b90224` прошёл x64/ARM64. У следующего `2cab475` ARM64 прошёл, x64 остановился при поиске IDE до GUI; исходная ошибка subprocess была скрыта wrapper-ом. Теперь в артефакт и annotation попадают обнаруженные/ожидаемые пути и коды неудачных probes. Поведение поиска и его проверки не ослаблены; причина прежнего сбоя не выдумывается.
