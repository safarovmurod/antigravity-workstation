## 3. Новые находки

### N1 (P3, только тестовая инфраструктура): тест quiet-completion падает на стандартной Windows — нет EPERM-guard для symlink

- **Файл/строка:** `tests/test-quiet-completion.mjs:154–160` — тест «Linked settings are rejected…» создаёт файловый symlink (`fs.symlinkSync`) без защиты.
- **Условие:** Windows без прав администратора/Developer Mode — создание файловых symlink запрещено (`EPERM -4048`). Это дефолтное состояние обычного пользовательского ноутбука.
- **Последствие:** основной `npm test` завершается **упавшим** (198 pass / 1 fail) вместо «220 passed». Красный набор маскирует реальные регрессии и делает зелёный прогон невозможным на типовой Windows-машине без ручного вмешательства.
- **Доказательство:** фактический прогон в этой среде: единственный падёж — именно этот тест с `Error: EPERM ... symlink`. При этом тот же класс тестов в `tests/test-audit-regressions.mjs:82–94` защищён паттерном `catch (error) { if (error.code === 'EPERM') return t.skip('File symlinks unavailable to this Windows user'); }` — и эти два теста корректно ушли в skip. Сиротский тест просто не перенял существующий в репозитории guard.
- **Не является:** продуктовым багом; на работу установленного setup не влияет. Исправление — тот же EPERM→skip guard (или запуск с правами, как CI), поведение проверять не нужно менять.

## 5. Наблюдения и гипотезы — сознательно НЕ подтверждённые баги

Не выдавать за находки без отдельного доказательства:

1. **WAL-ожидание после краша IDE** (`lib/agent-automation.js:183`): worker откладывает применение, пока существуют `-wal`/`-shm`. Если IDE **упал** (не закрылся) и больше не запускается, WAL никто не чекпойнтит, и worker будет ждать до 24-часового таймаута; статус честно показывает `waiting`. Лечится открытием/закрытием IDE. Нужен ли форс-чекпойнт при гарантированном отсутствии IDE — вопрос дизайна, требующий семантики «IDE точно не жив»; в доступной среде (без реальной Antigravity-БД с WAL) не воспроизводился.
2. **`decision: 'ask'` в `gsd-antigravity-adapter.cjs:105`** — факт подтверждён (как и в handoff), влияние на постоянные подтверждения в live chat пользователя по-прежнему не проверено. Не объявлять причиной; не заменять blanket allow без исследования host-семантики.
3. **`installExtension` (cmd-ветка) без таймаута** (`lib/extensions.js:93–98`): `execSync` установки gallery-extension без `timeout`, тогда как ts-mancho/stability пути имеют 120–180 с. Зависший CLI повесит установку. Гипотеза устойчивости, не воспроизводилась (нужен реально зависающий CLI).
4. **Несогласованная проверка символов путей:** ts-mancho/stability проверяют `/["%\r\n]/` в путях перед `execSync`, marketplace-fallback внутри `installExtension` — нет (путь берётся из `os.tmpdir()`/`mkdtemp`). Эксплуатируемость сомнительна (символ `%` должен оказаться в temp-пути), консистентность желательно выровнять при случае.
5. **`bin/mansur-setup.js:156`:** `status` возвращает exit 0 для состояния `invalid` (в отличие от `resume:164`, который возвращает 1). Формальная несогласованность кодов выхода; пользовательского вреда не показано.
6. **`quiet-completion` применяет файлы до нативной очереди** (`lib/quiet-completion.js:81–84`): при отказе `queueAutomation` файловые изменения уже применены (частичное применение; есть backup и статус). Осознанный компромисс, не скрытая потеря данных.
